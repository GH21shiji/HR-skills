# 冷启动交付模板

只在需要生成正式冷启动材料时读取本文件。

## 证据标签

- `事实`：有数据、制度、合同、系统记录或多方一致证据。
- `访谈观点`：明确写出信息来源和角色，不匿名扩散个人评价。
- `推断`：说明从哪些事实推导而来，并列出可能的其他解释。
- `假设`：暂时用于建模，必须写明验证方式和最晚验证时间。
- `待确认`：缺失后可能改变方案的信息。

## 组织尽调清单

### 业务

- 客户是谁，付费原因是什么；
- 当前收入、毛利和现金压力；
- 未来 6-12 个月里程碑；
- 关键流程和主要产能限制；
- 哪个假设一旦错误会改变人员计划。

### 治理

- 谁作出业务、预算、人员和薪酬决定；
- 决定前需要哪些信息和审批；
- 哪些会议真实产生决定；
- 哪些事项存在多人负责或无人负责。

### 组织与人才

- 关键岗位、单点风险和临时替代人；
- 关键人才的贡献证据、流失风险和发展需求；
- 团队能力缺口和招聘难度；
- 绩效、流失、缺勤和劳动争议趋势；
- HC 与成本是否支持业务计划。

## 风险登记表

| 编号 | 风险描述 | 类型 | 证据 | 可能性 | 影响 | 可逆性 | 应对动作 | 责任人 | 复查日 |
|---|---|---|---|---|---|---|---|---|---|

类型至少区分：业务、现金、关键人才、组织、招聘、绩效、劳动、数据与权限。

## 30/60/90 天计划

| 阶段 | 目标 | 动作 | 业务原因 | 负责人 | 依赖 | 成功指标 | 停止或改道条件 |
|---|---|---|---|---|---|---|---|
| 0-30 天 | 建立事实基础并处理急迫风险 |  |  |  |  |  |  |
| 31-60 天 | 建立必要机制并验证方案 |  |  |  |  |  |  |
| 61-90 天 | 扩展有效做法并进入常态运营 |  |  |  |  |  |  |

每个阶段通常保留 3-5 项重点。若更多，应说明资源来源和取舍。

## 管理层汇报顺序

1. 当前最重要的业务与组织事实；
2. 如果不采取行动，未来 30-90 天会发生什么；
3. 建议采取的少量动作；
4. 需要管理层现在决定什么；
5. 仍不确定什么，以及如何验证。
