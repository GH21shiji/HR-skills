# AI 原生招聘入职工作流规范

只在设计系统、字段、自动化或验收测试时读取本文件。

## 人机分工

| 工作类型 | AI 可做 | 必须人工处理 |
|---|---|---|
| 信息整理 | 提取、归类、查重、摘要、缺失检查 | 确认冲突信息和最终事实 |
| 评价辅助 | 按已批准标准比对证据、生成追问 | 录用、淘汰、定级和价值判断 |
| 流程运营 | 提醒、生成草稿、检查状态、统计指标 | 发送消息、改变状态或发起正式流程前授权 |
| 薪酬 Offer | 计算总报酬、内部比较、发现越界 | 定薪、例外审批和正式承诺 |
| 入职试用期 | 任务提醒、访谈提纲、材料汇总 | 转正、延期、不通过和劳动处置 |

## 候选人主记录

建议字段分为四类。

### 事实字段

- `candidate_id`：稳定唯一标识；
- 姓名、联系方式、简历来源、目标职位；
- 当前城市、期望工作地、可到岗时间；
- 工作经历、教育经历、作品或公开成果；
- 当前阶段、阶段更新时间、负责人。

### 计算字段

- 工作年限、流程停留时间、重复记录标识；
- 各阶段时长、面试完成度、材料完整度；
- Offer 预算差异、入职任务完成率。

### AI 生成字段

- 简历摘要、岗位证据、风险提示、面试追问；
- 面试记录摘要、不同意见、待验证事项；
- 数据冲突和缺失提示。

AI 字段应保存生成时间、依据和状态，例如“草稿 / 人工确认 / 已失效”。

### 人工决定字段

- 是否进入下一阶段；
- 录用或淘汰；
- 职级、薪酬和 Offer 方案；
- 背景调查结论；
- 转正、延期或不通过。

记录决定人、时间、审批依据和版本。自动化不能直接覆盖这些字段。

## 推荐状态机

```text
需求草稿 -> 待审批 -> 招聘中 -> 初筛 -> 面试中
-> 待决定 -> Offer审批 -> Offer已发 -> 已接受
-> 待入职 -> 已入职 -> 试用期中 -> 转正/延期/不通过
```

另设终止状态：需求取消、候选人退出、不匹配、Offer拒绝、未入职。终止原因使用结构化分类并允许补充事实说明。

## 自动化触发示例

| 触发 | 自动动作 | 人工审批点 | 失败处理 |
|---|---|---|---|
| 新增招聘需求 | 检查字段、生成需求澄清问题 | 发布 JD 前 | 缺关键字段则保持草稿 |
| 新增简历 | 查重、提取事实、生成证据摘要 | 推进阶段前 | 冲突或低置信度转人工 |
| 面试记录提交 | 汇总证据和未回答问题 | 录用或淘汰前 | 缺评价则提醒负责人 |
| Offer 审批通过 | 生成沟通草稿和入职任务 | 正式发送前 | 字段不一致则停止 |
| 候选人接受 | 创建入职准备清单 | 写入员工系统前 | 重复员工 ID 则停止 |
| 入职完成 | 创建试用期节点 | 正式目标确认 | 主管或目标缺失则升级 |

## 写入合同

任何自动写入都应满足：

1. 使用稳定记录 ID；
2. 写入前读取当前值和版本；
3. 只更新明确授权的字段；
4. 同一请求重复执行不会新增重复记录或重复发送；
5. 写入返回后重新读取；
6. 核对目标记录、字段和值；
7. 记录成功、跳过、冲突和失败数量；
8. 关键失败不继续执行后续外部动作。

## 最低权限设计

- 招聘人员只访问负责职位和必要候选人信息；
- 面试官只查看面试所需材料和本人评价；
- 薪酬、身份、健康和背景调查信息限制在有权角色；
- AI 使用的账号和工具只获得当前任务需要的权限；
- 导出和公开示例移除姓名、联系方式、真实记录 ID、Base 标识和公司专有数据。

## 验收用例

至少测试以下情况：

- 同一候选人从两个渠道进入时能识别重复；
- 姓名相同但候选人不同不会误合并；
- 简历和表单信息冲突时不会静默覆盖；
- 缺少工作地、预算或面试结论时不会自动推进；
- 未经授权不会发送消息或改变候选人状态；
- Offer 字段与审批结果不一致时停止并报告；
- 重复运行不会重复创建入职任务；
- 写入后能重新读取并核对成功；
- 试用期到期提醒准确，且没有自动生成劳动决定；
- 统计数据能与候选人明细核对。

## 指标

区分效率、质量和风险：

- 效率：各阶段中位时长、超时数、人工重复录入量；
- 质量：结构化评价完整率、关键字段缺失率、试用期通过后的早期绩效；
- 结果：Offer 接受率、到岗率、早期离职率；
- 风险：错误写入、重复记录、未授权动作、敏感信息暴露和人工推翻率。

指标用于改进流程，不自动证明某位招聘人员或候选人的能力。
